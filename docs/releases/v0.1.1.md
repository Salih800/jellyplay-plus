# JellyPlay+ 0.1.1

Superseded by [0.1.2](v0.1.2.md), which adopts the fork's final application ID:
`com.salih800.jellyplay.plus`.

Fixes the Android application ID collision in 0.1.0.

## Installation fix

- Phone releases now use `com.raulshma.jellyplay.plus`, so JellyPlay+ installs
  alongside the original JellyPlay (`com.raulshma.jellyplay`).
- Launcher shortcuts now resolve to each variant's actual application ID,
  including release, development, and TV variants.
- FileProvider and AndroidX Startup authorities already follow the application ID
  and are isolated automatically.
- Baseline-profile generation and startup benchmarks target the fork's release.
- Existing Dev builds keep `com.raulshma.jellyplay.dev` and their local data.

## Package

- Asset: `jellyplay-v0.1.1-phone-arm64-v8a.apk`.
- Android 9 (API 28) or newer; ARM64 phones and tablets.
- Version name: `0.1.1`; version code: `101`.
- Uses the same dedicated JellyPlay+ signing certificate as 0.1.0.
- Includes the download grouping, numeric episode ordering, episode counts, and
  bulk-selection improvements from 0.1.0.

The application ID change means this installs as a separate app, including for
people who installed JellyPlay+ 0.1.0. Settings and downloads from that app or
the Dev app are not automatically transferred. Keep existing apps and their data;
removing the original JellyPlay is not required.

## Validation

- Signed, optimized phone release build passed.
- APK package ID, version, signing certificate, all three provider authorities,
  and all six literal launcher shortcut targets were verified.
- Generated shortcut targets were checked for phone/TV and release/debug variants.
- Installed and launched on a Xiaomi 2201116TG running Android 13 alongside
  `com.raulshma.jellyplay` and `com.raulshma.jellyplay.dev`.
- The device registered all six shortcut intents against the `.plus` package.
- Both pre-existing packages retained their versions, APK paths, and update times.
- The release reached the server setup screen; no account was added and playback
  was not part of this package-identity check.
